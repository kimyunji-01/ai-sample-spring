# 아이디(username) 중복체크 기능 구현 보고서

이 보고서는 사용자가 회원가입 시 아이디가 중복되는지 실시간으로 확인하는 기능을 어떻게 구현했는지 설명합니다.

---

## 1. 무엇을 구현했나요?
사용자가 아이디를 입력하고 '중복확인' 버튼을 누르면, **페이지 전체를 새로고침하지 않고** 서버에 물어봐서 아이디 사용 가능 여부를 알려주는 기능을 만들었습니다.

---

## 2. 작업 과정 (쉽게 따라가기)

1.  **창고 확인 (Repository)**: 데이터베이스에서 특정 아이디가 있는지 찾아보는 기능을 확인했습니다.
2.  **판단 로직 추가 (Service)**: "이 아이디 있어?"라고 물으면 "응, 있어(true)" 또는 "아니, 없어(false)"라고 대답해주는 비즈니스 로직을 만들었습니다.
3.  **대화 창구 개설 (Controller)**: 브라우저가 서버에 데이터를 요청할 수 있는 주소(`/api/users/username-check`)를 만들었습니다.
4.  **화면 만들기 (Mustache & JS)**: 사용자가 볼 수 있는 입력창과 버튼을 만들고, 버튼을 누르면 서버와 몰래(?) 통신하는 자바스크립트 코드를 짰습니다.

---

## 3. 어려운 기술 설명 (Tech Talk)

이번 작업에 들어간 조금 어려운 개념들을 쉽게 설명해 드릴게요.

### 📡 Ajax & fetch (에이잭스 & 페치)
*   **설명**: 보통 웹사이트에서 버튼을 누르면 페이지가 '깜빡'하면서 전체가 새로 고쳐지죠? Ajax는 **페이지 전체를 바꾸지 않고 필요한 데이터만 몰래 주고받는 기술**입니다. 
*   **비유**: 식당에서 메뉴판 전체를 새로 받는 게 아니라, 종업원에게 "이 메뉴 품절인가요?"라고 살짝 물어보고 답만 듣는 것과 같습니다.

### ⏳ async/await (어싱크/어웨이트)
*   **설명**: 서버에 데이터를 요청하면 응답이 올 때까지 시간이 걸립니다. 이때 **응답이 올 때까지 기다렸다가 다음 코드를 실행**하게 해주는 마법 같은 키워드입니다. 
*   **비유**: 택배를 주문하고(async), 택배가 올 때까지 문앞에서 기다렸다가(await), 물건을 받는 과정과 비슷합니다. 이 방식 덕분에 복잡한 비동기 코드를 위에서 아래로 읽히는 쉬운 코드로 짤 수 있습니다.

### 📦 Resp (공통 응답 객체)
*   **설명**: 서버가 브라우저에게 대답할 때, 항상 **정해진 규격의 봉투**에 담아서 보내는 방식입니다. 
*   **비유**: 어떤 편지는 편지지에, 어떤 편지는 포스트잇에 써서 주면 받는 사람이 헷갈리겠죠? 항상 같은 모양의 '봉투(상태코드, 메시지, 실제 데이터)'에 담아 보내기로 약속한 것입니다.

### 🛡️ Optional & isPresent (옵셔널)
*   **설명**: 데이터가 "있을 수도 있고 없을 수도 있는" 상황을 안전하게 처리하는 자바 구조입니다. 
*   **비유**: 상자를 열어보기 전까지는 선물이 있는지 없는지 모르는 상태입니다. `isPresent()`는 "상자 안에 선물이 들어있니?"라고 물어보는 안전한 방법입니다.

## 4. 최종 결과
- **백엔드**: 중복 여부를 알려주는 API가 정상 작동합니다.
- **프론트엔드**: 중복 시 빨간색 메시지, 사용 가능 시 초록색 메시지로 사용자에게 즉시 알려줍니다.
- **빌드 상태**: `./gradlew classes` 통과 완료!

이제 사용자는 아이디 중복 때문에 회원가입에 실패하는 짜증 나는 경험을 하지 않아도 됩니다! 🚀
