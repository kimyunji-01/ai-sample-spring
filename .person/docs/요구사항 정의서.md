# 요구사항 정의서 (블로그 서비스)

## 1. 개요
누구나 가입하여 글을 쓰고 소통할 수 있는 심플한 커뮤니티형 블로그 서비스를 구축합니다.

## 2. 사용자 역할 (User Roles)
- **비회원 (Guest)**: 게시글 및 댓글 조회 가능.
- **회원 (User)**: 로그인 후 게시글/댓글 작성, 수정, 삭제 가능 (본인 작성 건에 한함).

## 3. 핵심 요구사항 (Key Requirements)

### 3.1. 회원 인증 (Authentication) [P0]
- 아이디, 비밀번호, 이메일을 이용한 회원가입 기능.
- 아이디/비밀번호 기반 로그인 및 세션(HttpSession) 관리.

### 3.2. 게시글 관리 (Board Management) [P0]
- **작성**: 제목과 본문으로 구성된 게시글 작성.
- **조회**: 게시글 상세 내용 조회.
- **수정**: 제목 및 본문 수정 기능.
- **삭제**: 게시글 삭제 기능.
- **기타**: 수정 시 수정 일자 표시 필수.

### 3.3. 댓글 관리 (Reply Management) [P0]
- **작성**: 게시글 하단에 단일 계층의 댓글 작성.
- **삭제**: 댓글 삭제 기능 (수정 기능 제외).
- **연쇄 삭제**: 게시글 삭제 시 해당 글의 모든 댓글 자동 삭제.

### 3.4. 목록 및 페이징 (List & Paging) [P1]
- 게시글 목록 조회 시 페이징 처리 지원.
- 최신순 정렬 기본 제공.

## 4. 제약 조건 및 전제 (Constraints)
- **도메인 기반 플랫 구조** 준수 (`com.example.demo/{domain}/`).
- **SSR**과 **REST API** 컨트롤러 분리 (`/api` 접두사 필수).
- **공통 응답** (`Resp<T>`) 사용.
- 게시글 카테고리, 태그, 썸네일 기능 제외.
- 게시글 검색 기능 제외.
- 대댓글 기능 제외 (단일 계층만 허용).

## 5. 엣지 케이스 및 에러 시나리오
- 본인이 작성하지 않은 글/댓글에 대한 수정/삭제 시도 시 적절한 에러 응답.
- 비로그인 사용자가 보호된 리소스(작성/수정/삭제) 접근 시 로그인 유도 또는 에러 응답.

## 6. 수용 기준 (Acceptance Criteria)
- [ ] 회원가입 및 로그인이 정상적으로 동작하는가?
- [ ] 게시글 작성/수정/삭제가 가능하며 수정 시 시간이 기록되는가?
- [ ] 게시글 목록이 페이징 처리되어 보이는가?
- [ ] 댓글이 정상적으로 작성/삭제되며 게시글 삭제 시 함께 삭제되는가?
